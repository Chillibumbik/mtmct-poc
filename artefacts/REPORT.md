# MTMCT PoC — отчёт о результатах

Версия: v2, 2026-11-03. Код — после волны исправлений по ревью (коммит `96cccab`), конфиги — итоговые.
Все цифры взяты из `outputs/<id>/metrics.json` и `runtime.json` прогонов `v2 · …`.
Номер прогона `#N` совпадает с номером в UI (страница «Эксперименты»; файлы прогона лежат в `outputs/00NNN/`).

## 1. Цель

Офлайн-система для видео с N синхронных камер: найти людей, провести каждого внутри камеры, присвоить один
глобальный ID одному человеку во всех камерах, измерить качество и показать всё в веб-интерфейсе. Работает только на
CPU, без обучения моделей: используются готовые открытые веса.

## 2. Данные и протокол

| Датасет | Тип | Камеры | Роль (сплит) | Людей (GT) |
|---|---|---|---|---|
| EPFL Terrace `terrace1` | реальный, перекрытие, 360×288 | 4 | dev (`all`); итоговых цифр нет | 9 |
| CAMPUS `garden1` / `garden2` | реальный, частичное перекрытие, 1080p, шумная калибровка | 4 | `garden1` = tune, `garden2` = test | 16 / 18 |
| WILDTRACK `main` | реальный, сильное перекрытие, 1080p, разметка 2 к/с | 7 | tune = первые 90 % кадров, test = последние 10 %, плюс `all` | 313 (41 в test) |
| AIC24 `scene_041` (4 из 10 камер) | синтетика, перекрытие | 4 | tune = 1-я половина времени, test = 2-я | 28 |
| CHIRLA `seq_001` / `seq_002` | реальный, помещения; профиль «без перекрытия» (на деле камеры 1–4 смотрят в одну комнату) | 7 (люди в 4–5) | `seq_001` = tune, `seq_002` = test | 9 / 9 |

- Пороги, веса и выбор профиля подбирались **только на tune**. Абляции на test только показывают вклад блоков и
  ничего не настраивают.
- Режимы: **oracle** (треклеты взяты из GT, поэтому детектор и трекер идеальны и видна ошибка только межкамерной
  ассоциации) и **full** (весь путь от видео).
- Метрики:
  - межкамерные (X): камеры склеиваются по времени в одну последовательность, по ней HOTA / IDF1 / AssA (TrackEval);
  - средние по камерам (pc): HOTA / IDF1 (камеры без людей не учитываются);
  - кластерные, на уровне треклетов: pairwise F1, ложные слияния и разбиения, число ID;
  - handover: доля переходов человека между камерами, при которых ID сохранился;
  - ReID rank-1.

## 3. Подход

```
видео N камер ─► детектор YOLOX-s ─► трекер ByteTrack ─► ReID OSNet-AIN ─► чистка треклетов (refine) ─┐
                 (oracle: GT-треклеты вместо детектора и трекера)                                    │
     портрет треклета (top-K кадров) ∥ геометрия (гомография + точка ног) ∥ окна переходов (topology) ◄┘
          ─► матрица стоимостей (взвешенное среднее + cannot-link) ─► агломеративная кластеризация
          ─► постобработка ─► global_tracks.csv ─► оценка (metrics.json) ─► UI
```

- **Профиль `overlap`:** внешний вид + мягкая геометрия на плоскости пола (вес 1, gate 1.5 м).
- **Профиль `nonoverlap`:** внешний вид + окна времени переходов между камерами.
- **Итоговые конфиги датасетов** (`configs/datasets/*.yaml`, всё выбрано на tune):

| Датасет | Геометрия | Порог решателя | Прочее | Почему |
|---|---|---|---|---|
| CAMPUS | мягкая, вес 0.5, gate 5 м | 0.55 | — | шумная калибровка |
| WILDTRACK | выключена | 0.30 | — | на full tune геометрия не помогла; в плотной толпе порог 0.45 сливает людей |
| AIC24 | мягкая, вес 1 | 0.65 | — | порог по oracle tune; на full tune кривая плоская |
| CHIRLA | — | — | стоимость времени выключена | раздел 6, H3 |

- **Главный рычаг качества full-режима** (T13a, garden1 tune) — разрез треклетов по скачку внешности
  (`refine.split_thr 0.75`, окно 7). Он дал межкамерный IDF1 +0.16 и сократил ложные слияния с 19 до 8.

## 6. Гипотезы

| ID | Гипотеза | Вердикт | Доказательство |
|---|---|---|---|
| H1 | Oracle даёт высокий IDF1, разрыв до full показывает долю ошибок до стыка | **подтверждена** | Разрыв oracle → full: 0.28–0.50 IDF1 на перекрывающихся наборах (5.1). Узкое место — детекция и трекинг внутри камеры (full pc IDF1 0.46–0.77). Исключение — CHIRLA: oracle тоже 0.77, т.е. ограничивает межкамерная ассоциация (сидящие люди, похожая одежда, ReID r1 0.69) |
| H2 | Геометрия сильнее внешнего вида при перекрытии | **подтверждена для чистых треклетов, не подтверждена на full** | На oracle геометрия решает: WILDTRACK test 0.707 → 0.981. На full tune мягкая геометрия даёт AIC24 +0.026, garden1 +0.015, WILDTRACK −0.012. На full test она хуже внешнего вида везде: terrace −0.009, garden2 −0.028, WILDTRACK −0.033, AIC24 −0.066 (5.2). Жёсткая — ещё хуже. Причины: точка ног по низу рамки на обрезанных и перекрытых рамках, загрязнённые треклеты, шумная калибровка CAMPUS |
| H3 | Окна переходов критичны без перекрытия | **отвергнута на CHIRLA** | С новой моделью связей камер (одновременно видимые пары = «нет информации») время ничего не даёт в oracle (0.769 = 0.769) и вредит в full: test 0.759 → 0.696, handover 0.88 → 0.50; tune 0.700 → 0.632. В CHIRLA почти нет настоящих переходов через коридор: окна в `topology.json` остались только для пары камер 3 ↔ 4 |
| H4 | Top-K портрет лучше среднего всех рамок | **не подтверждена** (результаты разнонаправленные) | Среднее всех рамок: garden2 0.643 против 0.586 (top-K), CHIRLA 0.713 против 0.759; ReID при этом в 3–4 раза дольше. Оговорка: `top_k=1000` ещё и эмбеддит все рамки, а это меняет работу refine |
| H5 | refine снижает ложные слияния | **подтверждена** | garden2: слияния 10 → 9, IDF1 0.486 → 0.586; CHIRLA: 4 → 3, IDF1 0.718 → 0.759; garden1 tune (T13a): 23 → 8 |

| H7 | Anchor-guided решатель лучше агломеративной | **не подтверждена** | garden2 0.517 против 0.586, CHIRLA 0.682 против 0.759 (пороги те же) |

## 7. Сравнение с литературой

Цифры напрямую несопоставимы:
- у нас нет обучения на целевых данных;
- метрика другая: IDF1 в пространстве изображения по склейке камер, а не BEV/3D;
- оцениваются все рамки, без маски зоны разметки.

| Набор | Наш результат | Литература (с обучением) |
|---|---|---|
| WILDTRACK test | full X IDF1 0.367 (#99); oracle с геометрией 0.981 (#29) | IDF1 на плоскости пола: ReST 86.7, EarlyBird 92.3, TrackTacular 95.3, UMPN 96.3 |
| CAMPUS Garden1 | full: X MOTA 0.641, X IDF1 0.639 (#95) | ReST: MOTA 77.6 (Garden1) |
| AIC24 | X HOTA 0.578 (2D, 4 камеры, val `scene_041`, #133) | AIC24: 3D HOTA ~81 (MCBLT 81.22); AIC23: IDF1 95.4 (синтетика, дообученные модели) |

WILDTRACK отстаёт из-за детекции (pc DetA 0.28):
- разметка покрывает только зону 12 × 36 м и не все видимые фигуры;
- рамки получены проекцией 3D-цилиндра;
- поэтому при IoU 0.5 recall детектора 0.58, а precision 0.48 (`agent-dump/scripts/t13b_detrecall.py`).

Работы из литературы считают метрики на плоскости пола внутри этой зоны.

## 8. Исправления после ревью (v1 → v2)

| Исправление | Эффект на цифры |
|---|---|
| `refine` интерполирует только на обработанные кадры (раньше при 25 → 10 к/с появлялись рамки на необработанных кадрах) | terrace1 full: X IDF1 0.496 → 0.501, X HOTA 0.402 → 0.417 (#24 → #131). CAMPUS, CHIRLA, AIC24 — без изменений (целый шаг кадров) |

| Модель связей камер для частичного перекрытия: одновременно видимые пары = «нет информации»; `topology.json` CHIRLA пересчитан | CHIRLA test, + время: 0.592 → 0.696, handover 0.13 → 0.50 (#39 → #111). ## 9. Ограничения

- **Качество треклетов — главное узкое место.** Переход oracle → full теряет 0.3–0.5 IDF1. Потолок garden1 при
  идеальной ассоциации тех же треклетов — X IDF1 0.80 (T13a), достигнуто 0.64. Треклеты фрагментированы (~10 на
  человека на камеру), DetA 0.5–0.67.
- **Геометрия помогает только на чистых треклетах.** На full она нестабильна: на tune небольшой плюс, на test минус.
- **Пороги привязаны к модели ReID.** Пороги refine и решателя заданы на шкале косинуса конкретной модели: при смене
  модели их нужно перенастраивать.
- **Шум оценок:**
  - в CHIRLA всего 9 человек, многие сидят на месте;
  - AIC24 оценивался на 4 из 10 камер;
  - каждая цифра — одна последовательность без доверительных интервалов; разброс между соседними конфигами
    ±0.015 HOTA (T13a).
- **Знаки tune и test расходятся.** Например, геометрия на AIC24: +0.03 на tune и −0.07 на test.
- **Долгие oracle-прогоны.** На крупных наборах oracle идёт 2.5–6 мин, дольше цели в 2 мин: ReID считается для всех
  GT-рамок.

## 10. Следующие шаги

1. **Треклеты:** склейка фрагментов внутри камеры (кластеризация по внешности до межкамерной), вес портрета по длине
   треклета, дополнительный сигнал разреза (скачок положения или размера рамки).
2. **Детектор:** прямоугольный вход без паддинга (например 1088×608), маска зоны разметки для WILDTRACK, ONNX Runtime
   для YOLOX (на этой машине на 15–20 % быстрее).
3. **Геометрия:**
   - точка ног по позе (H9);
   - геометрию учитывать только для чистых и длинных треклетов (вес по качеству);
   - gate подбирать на full tune.
4. **Модели ReID:** хранить таблицу порогов для каждой модели. Подобрать пороги OMZ-0287 на tune и рассмотреть её как
   модель по умолчанию — на garden2 она быстрее и лучше.
5. **Re-ranking и anchor-решатель:** подбирать для них порог на tune отдельно.
6. **Профиль без перекрытия:** проверить на последовательностях CHIRLA с переходами между помещениями (seq_004+).

## 11. Как воспроизвести в UI

1. Запустите `make dev` (или `uv run mtmct api` и `uv run mtmct worker`) и откройте <http://localhost:5173>.
2. На странице «Данные» все наборы должны быть в статусе ready, прокси-видео для плеера уже построены.
3. «Новый прогон»: выберите датасет, последовательность, сплит (`tune` / `test` / `all`) и режим `full` или `oracle`,
   профиль оставьте по умолчанию — получится строка таблицы раздела 4. Абляции задаются переопределениями:
   - `associate.costs.geometry.weight = 0`
   - `refine.enabled = false`
   - `portrait.top_k = 1000`
   - `associate.solver.name = anchor`
   - `associate.rerank = {k1: 20, k2: 6, lambda_: 0.3}`
   - `reid.name`, `detect.name`
4. Готовые сетки лежат в `configs/sweeps/v2_*.yaml` (тела `RunCreate` / `SweepCreate`). Отправка:
   `uv run python agent-dump/scripts/t13b_submit.py configs/sweeps/<файл>.yaml`. Тяжёлые стадии кешируются, поэтому
   повтор ассоциации занимает секунды.
5. «Эксперименты» → выберите прогоны (например #97, #102, #103) → «Сравнить». На странице «Прогон» есть кривая порога,
   переходы между камерами, «Ошибки» и «Плеер» с глобальными ID.

## 12. Дообучение (FT)

Дообучены две модели на открытых данных, только на tune-сплитах: campus/garden1, WILDTRACK (первые 90 % времени),
AIC24 scene_041 (первая половина, все 10 камер), CHIRLA seq_001, EPFL terrace1 (dev). garden2, CHIRLA seq_002,
вторая половина AIC24 и последние 10 % WILDTRACK в обучение не попадали; это проверяет тест
`test_ft_dataset_respects_tune_split`. Конфиги выбирались на tune, на test запускался один выбранный конфиг.
Подробности: `agent-dump/reports/FT_report.md`. Прогоны #134–#211 (`ft · …`).

- **ReID** `reid/osnet_ain_x1_0_ft`: OSNet-AIN x1_0 из MSMT17, CE + triplet на 24 тыс. GT-кропов, 72 мин CPU. На
  отложенных людях (не участвовали в обучении) rank-1 0.836 → 0.915, mAP 0.577 → 0.735. У модели другая шкала косинуса:
  refine split/stitch 0.95 вместо 0.75.
- **Детектор** `detector/yolox_s_ft`: YOLOX-s из COCO, официальный код YOLOX (Apache-2.0), 1.5 тыс. кадров, 85 мин CPU,
  conf 0.6 (выбран на tune). Для WILDTRACK — отдельный вариант `detector/yolox_s_ft_wt` (+ кадры WILDTRACK tune,
  8 мин на GPU), conf 0.5. Общий детектор на WILDTRACK хуже базы: разметка только зоны 12 × 36 м и рамки-цилиндры.
- Скорость инференса не меняется: архитектуры те же.

- **Детектор — главный рычаг.** Recall / precision при IoU 0.5:
